## Notes — why Guid v7 wins

_Hand-written analysis — preserved across re-runs. The exact numbers above change per run; the shape holds._

- **Bulk insert** — the largest, most stable gain. Random UUIDs cause constant B-tree page splits as the
  index must reorder every incoming key; time-ordered Guid v7 keys always append to the rightmost leaf, so
  splits are rare.
- **Index size** — at large scale Guid v7 can produce a *larger* index despite being faster: random inserts
  leave partially-filled pages after splits, while ordered inserts pack pages densely but reuse fewer.
- **Batched VALUES** — a big gain too: with random UUIDs the single statement still triggers many index
  rebalances; with v7 the tree barely changes shape.
- **Point lookups** — v7 keys cluster related rows on the same index pages, improving cache hit rate.
- **The small `+100 rows` steps are noisy** (high ±CV%) — read them as "roughly even", not as real wins or
  losses. The dominant cost there is fsync per transaction, which key order does not change.
